# 关键技术实现 / Technical Details

## 一、整体架构

```
┌─────────────────────────────────────────────────┐
│  设备端 (ESP32-S3 / 小智 v2.4.2 + ESP-IDF 5.5)   │
│  ┌───────────┐  ┌────────────┐  ┌────────────┐  │
│  │ WordCard  │  │  MCP Server│  │  LVGL UI   │  │
│  │ (1Hz 定时)│  │ (3 个工具)  │  │  (摆件卡)   │  │
│  └─────┬─────┘  └─────┬──────┘  └─────┬──────┘  │
│        │              │               │         │
│        └──── 数据 ────┴──── 刷新 ─────┘         │
└───────────────────────┬─────────────────────────┘
                        │ WebSocket / MCP
┌───────────────────────▼─────────────────────────┐
│  云端 xiaozhi.me                                  │
│  唤醒词检测 → 流式 ASR → LLM（教学主持）→ TTS      │
└─────────────────────────────────────────────────┘
```

核心设计原则：**设备端只做数据和显示，教学逻辑交给云端大模型**。这样不用在 MCU 上实现语音识别和自然语言理解，代码量小、可维护、能随模型能力升级而升级。

## 二、摆件界面（word_card.h）

- **驱动方式**：`esp_timer` 每秒触发一次 `OnTick()`，检查设备状态和各字段是否变化，变了才刷新，避免无谓重绘。
- **自动显隐**：读取 `Application::GetInstance().GetDeviceState()`，只在 `kDeviceStateIdle`（空闲）时显示；一旦说话/唤醒进入 `Speaking`/`Listening`/`Connecting` 等状态立即隐藏。
- **中文显示**：从资源分区取 `font_noto_sans_common_20_4.bin`（6845 常用汉字 + 音标符号），用 `LvglCBinFont` 加载，中文释义和音标都能正常显示。
- **对时**：`esp_sntp` 轮询模式，`TZ=CST-8`，阿里云 + pool.ntp.org 双服务器；收到同步回调后置位标志，界面从 `--:--` 切到真实时间。
- **打卡逻辑**：`Settings("word_card")` 存 NVS，记录 `last_day` / `streak`；今天已记过不重复加，昨天连续则 +1，断天归零。

## 三、AI 跟读打分（MCP 工具）

注册三个工具（`zhengchen-1.54tft-wifi.cc` 的 `InitializeTools()`）：

| 工具 | 触发场景 | 返回 |
|---|---|---|
| `self.word.get_today` | 用户说"教我读单词/背单词/跟读" | 当前词条 JSON + 教学指令 |
| `self.word.next` | 用户说"下一个/换一个" | 下一条词 JSON + 教学指令 |
| `self.word.mark_passed` | 大模型判断用户念对后调用 | `true`，设备端打卡 +1 |

`get_today` 返回的 JSON 里带一段 `instruction` 字段，本质是"提示词注入"——把教学 SOP 写进工具返回值，让云端 LLM 按步骤主持课堂：

1. 慢速念单词 → 2. 报音标释义 → 3. 邀请跟读 → 4. 对比 ASR 文本判断对错、纠正重音 → 5. 念对则调 `mark_passed` 打卡 → 6. "下一个"调 `next` 换词。

**为什么这样设计**：
- 发音判断靠云端 ASR 转写 + LLM 语义比对，MCU 完全不用跑语音模型。
- 工具回调只做数据读写（不碰 LVGL），界面变化由 1Hz 定时器统一带 `DisplayLockGuard` 刷新，规避多线程操作 UI 的风险。
- 词库、教学话术都是纯数据，改起来不用碰底层。

## 四、词库（word_data.h）

```cpp
struct WordEntry {
    const char* word;
    const char* phonetic;
    const char* meaning;
};
```

直接改 `kWordBook` 数组即可加词。今日词条 = `(天数时间戳 % 词库大小)`，按天自动轮换；会话内"下一个"用 `session_offset_` 偏移。

## 五、编译与资源

- 主固件 `xiaozhi.bin` 约 3.04MB，app 分区（0x3f0000）剩余约 26%。
- 中文字库不占 app 分区，放在 `generated_assets.bin`（1.59MB，烧到 0x800000）。
- 修改只涉及 board 目录下 3 个文件，增量编译只需重编 1 个编译单元 + 链接，约 1 分钟。

## 六、已知限制 / 后续迭代

- 发音判断依赖云端 ASR 对英文单词的转写质量，重音/连读的细粒度评分还需更专业的音素级评估。
- 设备会被云端 OTA 自动升级覆盖自定义固件；量产建议关闭自动 OTA。
- 唤醒词是 WakeNet 预训练模型，不能随意改成任意自定义词（如"你好核桃"需要找乐鑫定制模型）。
